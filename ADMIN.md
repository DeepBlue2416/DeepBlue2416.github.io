# Админ-панель, токен и безопасность

## Как работает админка (`/admin.html`)
Оператор открывает `https://ВАШ-САЙТ/admin.html`, вводит **URL воркера** и **ADMIN_TOKEN**,
и получает таблицу товаров с быстрым редактированием цены и статуса. Кнопка «Сохранить»
отправляет изменения в Cloudflare KV через воркер, и витрина сразу отдаёт новые цены —
пересобирать сайт не нужно.

Токен **не хранится** в браузере (только в памяти вкладки до перезагрузки) и **не лежит** в коде.

## 1. Как сгенерировать ADMIN_TOKEN
Возьмите длинную случайную строку (32+ байта). Любой способ:

```bash
openssl rand -hex 32
# или
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Скопируйте полученную строку — это и есть токен. Придумывать «пароль руками» не нужно.

## 2. Где хранить токен (безопасно)
Токен хранится как **секрет Cloudflare Worker**, а не в репозитории:

```bash
cd worker
npx wrangler secret put ADMIN_TOKEN
# вставьте сгенерированную строку
```

Воркер сравнивает присланный `Authorization: Bearer <token>` со своим секретом
(функция `authorized()` в `worker/index.js`, сравнение защищено от тайминг-атак).
Меняете токен — просто выполните `wrangler secret put ADMIN_TOKEN` заново.

Так же задаются остальные секреты:
```bash
npx wrangler secret put TELEGRAM_BOT_TOKEN
npx wrangler secret put TELEGRAM_CHAT_ID
npx wrangler secret put TURNSTILE_SECRET   # секретный ключ Turnstile (проверка капчи)
```

## 3. Первый запуск: залить каталог в KV
1. Откройте `admin.html`, введите URL воркера и токен → «Войти».
2. Нажмите **«Инициализировать KV»** — каталог из `products.js` загрузится в KV (ключ `catalog`).
3. Дальше правьте цены/статусы прямо в таблице → «Сохранить» (или ⌘/Ctrl+S).

> Локально (открытие `admin.html` файлом) KV недоступен, поэтому админка работает в
> демо-режиме только для чтения. Реальное сохранение — после деплоя воркера.

## 4. Rate-limit (защита от спама заявок)
Реализован в `worker/index.js`, функция `rateLimited()` — не более **5 заявок с одного IP
за 60 секунд**, счётчик хранится в KV (`rl:<ip>` с TTL). При превышении воркер отвечает `429`.

Отдельная настройка не нужна — используется тот же KV-неймспейс `PRODUCTS`, что и для каталога.
Поменять лимиты можно в начале функции:
```js
const LIMIT = 5, WINDOW = 60; // заявок / секунд
```
KV имеет «мягкую» согласованность (значения расходятся между регионами за секунды), поэтому
лимитер приблизительный — для базовой анти-спам-защиты этого достаточно. Для строгих лимитов
используйте Cloudflare Rate Limiting Rules на уровне зоны.

## 5. Ошибка `GET /api/products 405 (Method Not Allowed)`
Это значит, что по адресу из `CONFIG.apiBase` задеплоена **старая версия воркера**, которая не
обрабатывает `GET /api/products`. Актуальный `worker/index.js` из этого репозитория его поддерживает.
Решение — передеплоить воркер:

```bash
cd worker
npx wrangler deploy
```

Пока воркер отдаёт ошибку, сайт автоматически показывает встроенный каталог (`products.js`),
поэтому витрина работает — но цены не берутся из KV в реальном времени, пока воркер не обновлён.
